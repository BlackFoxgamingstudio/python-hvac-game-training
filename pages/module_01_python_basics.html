Python Fundamentals

The Language of Systems

You read sensor values every day — 72°F supply air, 410 PSI discharge pressure, 65% relative humidity. In Python, those values live in variables. Your thermostat logic? That's an if/elif/else statement. The refrigeration cycle that runs over and over? That's a loop. Let's translate what you already know into code.

📐 1.1 — Variables: Your Digital Sensor Readings

In HVAC, you read values from sensors constantly. A supply air temperature sensor might read 55°F. A suction pressure transducer shows 68 PSI. A humidity sensor reports 52%. In Python, we store these values in variables — named containers that hold data.

Think of a variable like a label on a piece of test equipment. The label tells you what it measures, and the reading is the current value. Here's how you create variables in Python: 

# HVAC Sensor Readings as Python Variables
# Each variable stores one piece of data from our system

supply_air_temp = 55.0       # Float: temperature in °F (decimal number)
return_air_temp = 72.0       # Float: what's coming back from the space
discharge_pressure = 410     # Integer: PSI (whole number)
suction_pressure = 68        # Integer: PSI
relative_humidity = 52.5     # Float: percentage
system_running = True        # Boolean: True or False (like a status light)
unit_name = "RTU-01"         # String: text in quotes
refrigerant_type = "R-410A"  # String: the refrigerant type

Python Data Types — The Four You Need

Every value in Python has a type. Just like how a temperature reading is different from a part number, Python distinguishes between different kinds of data:

# Check the type of each variable
print(type(supply_air_temp))    # <class 'float'>

print(type(unit_name))          # <class 'str'>
print(type(system_running))     # <class 'bool'>

📟 1.2 — f-Strings: Sensor Readout Display

When you read a gauge, you don't just see "72" — you see "72°F Return Air Temperature." Context matters. In Python, f-strings (formatted string literals) let you embed variables inside text, creating readable sensor readouts.

An f-string starts with the letter f before the opening quote, and you put variable names inside curly braces {}. Python replaces them with the actual values: 

# Sensor Readout Display Using f-strings
supply_air_temp = 55.3
return_air_temp = 72.0
discharge_pressure = 412
suction_pressure = 68
unit_name = "RTU-01"

# Basic readout
print(f"Unit: {unit_name}")
print(f"Supply Air: {supply_air_temp}°F")
print(f"Return Air: {return_air_temp}°F")

# Calculate and display delta-T (temperature difference)
delta_t = return_air_temp - supply_air_temp
print(f"Delta-T: {delta_t:.1f}°F")  # .1f = 1 decimal place

# Full system status report
print(f"""
╔══════════════════════════════════════╗
║  SYSTEM STATUS: {unit_name:>10}         ║
╠══════════════════════════════════════╣
║  Supply Air Temp:   {supply_air_temp:>6.1f}°F        ║
║  Return Air Temp:   {return_air_temp:>6.1f}°F        ║
║  Delta-T:           {delta_t:>6.1f}°F        ║
║  Discharge PSI:     {discharge_pressure:>6}           ║
║  Suction PSI:       {suction_pressure:>6}           ║
╚══════════════════════════════════════╝
""")

The :.1f format specifier means "show 1 decimal place." The :>6 means "right-align in a 6-character wide field." These formatting tricks help you build clean, professional readouts — just like the display on a modern thermostat.

🔢 1.3 — Operators: HVAC Math in Python

HVAC work is full of calculations — CFM, BTU, tonnage, superheat, subcooling. Python operators let you do all this math. Let's start with the most common calculation every tech knows: Fahrenheit to Celsius conversion. 

# ═══ Temperature Conversion ═══
# The formula: °C = (°F - 32) × 5/9

supply_air_f = 55.0
supply_air_c = (supply_air_f - 32) * 5 / 9

print(f"Supply Air: {supply_air_f}°F = {supply_air_c:.1f}°C")
# Output: Supply Air: 55.0°F = 12.8°C

# ═══ Superheat Calculation ═══
# Superheat = Actual Suction Line Temp - Saturated Suction Temp
actual_suction_temp = 48.0   # °F — measured with thermometer
saturated_suction_temp = 40.0 # °F — from PT chart at suction pressure

superheat = actual_suction_temp - saturated_suction_temp
print(f"Superheat: {superheat:.1f}°F")
# Output: Superheat: 8.0°F

# ═══ Subcooling Calculation ═══
# Subcooling = Saturated Condensing Temp - Actual Liquid Line Temp
saturated_condensing_temp = 120.0  # °F — from PT chart at discharge pressure
actual_liquid_line_temp = 110.0    # °F — measured

subcooling = saturated_condensing_temp - actual_liquid_line_temp
print(f"Subcooling: {subcooling:.1f}°F")
# Output: Subcooling: 10.0°F

# ═══ Delta-T (Temperature Split) ═══
return_air = 75.0
supply_air = 55.0
delta_t = return_air - supply_air
print(f"Delta-T: {delta_t:.1f}°F (target: 15-22°F)")
# Output: Delta-T: 20.0°F (target: 15-22°F)

🌡️ 1.4 — Conditionals: The Thermostat Pattern

A thermostat is the most fundamental conditional in HVAC: "If the temperature is above the setpoint, turn on cooling. If it's below, turn on heating. Otherwise, do nothing." In Python, that exact logic looks like this: 

# ═══ Basic Thermostat Logic ═══
room_temp = 76.0
cooling_setpoint = 72.0
heating_setpoint = 68.0

if room_temp > cooling_setpoint:
    print(f"🔵 COOLING ON — Room is {room_temp}°F (setpoint: {cooling_setpoint}°F)")
    print(f"   Need to drop {room_temp - cooling_setpoint:.1f}°F")
elif room_temp < heating_setpoint:
    print(f"🔴 HEATING ON — Room is {room_temp}°F (setpoint: {heating_setpoint}°F)")
    print(f"   Need to raise {heating_setpoint - room_temp:.1f}°F")
else:
    print(f"✅ DEADBAND — Room is {room_temp}°F (comfortable range)")
    print(f"   System idle, no action needed")

Let's break down the syntax. The word if starts the check. The condition (room_temp > cooling_setpoint) must be either True or False. If it's True, the indented code underneath runs. If not, Python checks the elif (short for "else if"). If nothing matches, the else block runs as a fallback.

Advanced: Multi-Stage Cooling with Fault Detection

# ═══ Multi-Stage Cooling Controller ═══
# Real commercial systems have multiple stages of cooling

room_temp = 82.0
setpoint = 72.0
stage_1_threshold = 2.0   # 2°F above setpoint → Stage 1
stage_2_threshold = 5.0   # 5°F above setpoint → Stage 2
emergency_threshold = 15.0 # 15°F above → something is wrong

deviation = room_temp - setpoint

if deviation > emergency_threshold:
    print(f"🚨 EMERGENCY — Room at {room_temp}°F!")
    print(f"   {deviation:.1f}°F above setpoint — possible equipment failure")
    print(f"   ACTION: Check compressor, check refrigerant charge")
elif deviation > stage_2_threshold:
    print(f"⚡ STAGE 2 COOLING — Room at {room_temp}°F")
    print(f"   {deviation:.1f}°F above setpoint — both compressors running")
elif deviation > stage_1_threshold:
    print(f"🔵 STAGE 1 COOLING — Room at {room_temp}°F")
    print(f"   {deviation:.1f}°F above setpoint — one compressor running")
elif deviation > 0:
    print(f"⏳ NEAR SETPOINT — Room at {room_temp}°F")
    print(f"   {deviation:.1f}°F above — within deadband, monitoring")
else:
    print(f"✅ AT SETPOINT — Room at {room_temp}°F")
    print(f"   System satisfied")

🔄 1.5 — While Loops: The Cooling Countdown

When your AC starts cooling a hot room, the temperature doesn't drop instantly. It decreases cycle by cycle, degree by degree. In Python, a while loop repeats code as long as a condition is True — just like your AC runs until the room reaches setpoint. 

# ═══ Cooling Countdown Loop ═══
# Simulate an AC cooling a room from 85°F down to the 72°F setpoint

room_temp = 85.0
setpoint = 72.0
cooling_rate = 1.5    # degrees dropped per cycle
cycle_count = 0

print("🔵 AC SYSTEM STARTING...")
print(f"   Room: {room_temp}°F → Target: {setpoint}°F")
print(f"   Cooling rate: {cooling_rate}°F per cycle")
print("-" * 40)

while room_temp > setpoint:
    cycle_count += 1  # same as: cycle_count = cycle_count + 1
    room_temp -= cooling_rate  # same as: room_temp = room_temp - cooling_rate

    # Don't overshoot the setpoint
    if room_temp < setpoint:
        room_temp = setpoint

    print(f"   Cycle {cycle_count:>2}: Room temp = {room_temp:.1f}°F")

print("-" * 40)
print(f"✅ SETPOINT REACHED in {cycle_count} cycles!")
print(f"   Final room temp: {room_temp}°F")

The Anatomy of a While Loop

Let's break down what's happening line by line:

  1. while room_temp > setpoint: — This is the condition. Python checks it before every cycle. If True, the indented block runs. If False, the loop ends.
  2. cycle_count += 1 — The += operator adds 1 to the counter. This is called incrementing.
  3. room_temp -= cooling_rate — The -= operator subtracts the cooling rate. Each cycle, the room gets cooler.
  4. The if room_temp < setpoint inside the loop prevents overshooting — we clamp to the setpoint, just like a real thermostat.

⚠️ Warning: Infinite Loops

If the condition never becomes False, the loop runs forever — like an AC that never shuts off because the thermostat wire is shorted. Always make sure your loop has a way to end. In our example, room_temp decreases each cycle, so eventually room_temp > setpoint becomes False and the loop stops. 

# ═══ Advanced: Runtime Monitoring with While Loop ═══
# Monitor a system and track min/max readings over time

import random  # We'll use this to simulate sensor noise

room_temp = 72.0
setpoint = 72.0
cycles = 0
max_temp = room_temp
min_temp = room_temp

print("📊 RUNTIME MONITORING — Press Ctrl+C to stop")
print("-" * 45)

# Run for 20 simulated cycles
while cycles < 20:
    cycles += 1

    # Simulate real-world temp fluctuation (+/- 2 degrees)
    fluctuation = random.uniform(-2.0, 2.0)
    room_temp = setpoint + fluctuation

    # Track min/max
    if room_temp > max_temp:
        max_temp = room_temp
    if room_temp < min_temp:
        min_temp = room_temp

    # Status indicator
    if abs(room_temp - setpoint) > 1.5:
        status = "⚠️ DRIFT"
    else:
        status = "✅ OK   "

    print(f"   [{cycles:>3}] Temp: {room_temp:>5.1f}°F  {status}")

print("-" * 45)
print(f"📈 Summary: Min={min_temp:.1f}°F  Max={max_temp:.1f}°F  Range={max_temp-min_temp:.1f}°F")

🛠️ 1.6 — Putting It All Together: Mini Thermostat Program

Let's combine everything from this module into one complete program. This simulates a smart thermostat that reads a temperature, decides what to do, and logs the action: 

# ═══ MINI THERMOSTAT SIMULATOR ═══
# Combines: variables, f-strings, operators, conditionals, loops

# ── Configuration ──
unit_name = "RTU-01"
cooling_setpoint = 72.0
heating_setpoint = 68.0
deadband = 2.0
room_temp = 85.0  # Starting temperature (hot day)
cooling_rate = 1.8
cycle = 0

# ── Header ──
print(f"""
╔════════════════════════════════════════════╗
║     THERMOSTAT SIMULATOR: {unit_name}          ║
╠════════════════════════════════════════════╣
║  Cooling SP: {cooling_setpoint:>5.1f}°F                       ║
║  Heating SP: {heating_setpoint:>5.1f}°F                       ║
║  Start Temp: {room_temp:>5.1f}°F                       ║
╚════════════════════════════════════════════╝
""")

# ── Main Control Loop ──
while room_temp > cooling_setpoint:
    cycle += 1

    # Determine mode
    if room_temp > cooling_setpoint + 5:
        mode = "STAGE 2"
        rate = cooling_rate * 1.5  # Both compressors
    elif room_temp > cooling_setpoint:
        mode = "STAGE 1"
        rate = cooling_rate
    else:
        mode = "IDLE"
        rate = 0

    # Apply cooling
    room_temp -= rate
    if room_temp < cooling_setpoint:
        room_temp = cooling_setpoint

    # Convert to Celsius for international readout
    room_temp_c = (room_temp - 32) * 5 / 9

    # Display
    print(f"  Cycle {cycle:>2} | {room_temp:>5.1f}°F ({room_temp_c:>5.1f}°C) | Mode: {mode}")

# ── Summary ──
print(f"\n✅ Setpoint reached in {cycle} cycles.")
print(f"   Final temp: {room_temp:.1f}°F / {(room_temp - 32) * 5/9:.1f}°C")
print(f"   System mode: SATISFIED")

🎯 Module 1 Key Takeaways

  • Variables store sensor data — temperatures, pressures, names, states.
  • Types define what kind of data: int, float, str, bool.
  • f-strings format your readouts: f"Temp: {temp:.1f}°F"
  • Operators do HVAC math: + - * /
  • Conditionals make decisions — exactly like thermostat logic.
  • While loops repeat until a condition is met — like cooling until setpoint.
