🖥️ 10.1 — AST Basics: Abstracting Python Syntax

Before Python runs code, it translates raw characters into a structural tree called an Abstract Syntax Tree (AST). The AST represents the logical nodes of the syntax — classes, functions, variable assignments, loops, and conditions — discarding whitespace and comments.

In systems engineering, this is comparable to compiling a structural blueprint from layout notes. Python's built-in ast module allows us to inspect these node structures directly:

🖥️ 10.2 — Lexical Analysis: Breaking Down Tokens

Compilation starts with Lexing (Tokenization). The compiler scans characters and groups them into syntax tokens — like keywords (class, def), operators (+, =), and identifiers.

If the lexer encounters invalid sequences (such as mismatched parentheses or invalid string quotes), it throws a tokenization error before the program can parse structural blocks.

🖥️ 10.3 — Syntax Validation: Class Defs and Init Methods

In our grading loop, we validate that students declare the class structures correctly. We check if a `ClassDef` node named `AirConditioner` is present, and check if it contains a `FunctionDef` corresponding to `__init__`: 

# --- AST Node Visitor Pattern Validator ---
print("==================================================")
print("🕵️ STORY LOG: Code Inspector Daemon")
print("==================================================")
print("Narrative: The system security engine starts up a")
print("compilation daemon. It walks the code's parsed nodes")
print("to check if the 'AirConditioner' class was defined.")
print("--------------------------------------------------")

import ast

class HVACValidator(ast.NodeVisitor):
    def __init__(self):
        self.has_class = False
        
    def visit_ClassDef(self, node):
        if node.name == "AirConditioner":
            self.has_class = True
            print(f"[DAEMON] Node MATCH: Found ClassDef named '{node.name}'")
        self.generic_visit(node)

# Simulate inspecting a student script AST
sample_tree = ast.parse("class AirConditioner:\n    pass")
validator = HVACValidator()
validator.visit(sample_tree)
print(f"[DAEMON] Scan completed. Class present? {validator.has_class}")

print("--------------------------------------------------")
print("💡 LEARNING OBJECTIVE: Create object-oriented NodeVisitor")
print("   subclasses to search syntax nodes dynamically.")
print("🎮 GAMEPLAY LINK: Resolving compile errors allows the robot")
print("   to patch broken grid control circuits.")
print("==================================================")

🖥️ 10.5 — Grading Engine: Scoring and Metrics Verification

The automated LMS compiler grades assignments by assigning scores to node presence. Finding a class contributes 40 points, a constructor constructor parameters yields 30 points, and active functions add the remaining 30 points to score 100/100. 

# --- Grading Engine Score Calculation ---
print("==================================================")
print("📊 STORY LOG: Academy Progress Report")
print("==================================================")
print("Narrative: The final exam results are computed. Each")
print("correct node found in your submission adds points to")
print("your master engineer progression record.")
print("--------------------------------------------------")

class MockValidator:
    def __init__(self):
        self.has_class = True
        self.has_init = True
        self.has_update = False

def compute_grade(validator):
    score = 0
    print("[GRADING] Scoring components:")
    if validator.has_class:
        score += 40
        print("  +40 pts: ClassDef 'AirConditioner' confirmed.")
    if validator.has_init:
        score += 30
        print("  +30 pts: Constructor '__init__' confirmed.")
    if validator.has_update:
        score += 30
        print("  +30 pts: Update loop method confirmed.")
    print(f"[GRADING] Cumulative Score: {score}/100")
    return score

# Score the validator
val = MockValidator()
compute_grade(val)
