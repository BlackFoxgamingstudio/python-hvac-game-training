OOP Refactor

Robot + AC Composition

Right now, your AC functions float around independently — like loose parts on a workbench. In the real world, those parts are assembled into a unit — an RTU, a split system, a chiller. In Python, we assemble related data and functions into a class. Then we compose bigger objects from smaller ones: a Robot that has an AirConditioner.

🧱 4.1 — What Is a Class?

A class is a blueprint for creating objects. An object is a specific instance of that blueprint. Think of it this way:

HVAC WorldPython World
Equipment spec sheet (the design)Class definition (the blueprint)
Actual unit on the roof: RTU-01Object instance: rtu_01 = AirConditioner()
Serial number, capacity, refrigerant chargeAttributes: self.capacity, self.charge
Start cooling, run diagnostic, defrostMethods: .cool(), .diagnose()

The class bundles data (attributes) and behavior (methods) into one unit. Instead of separate variables and functions, everything about an AC lives inside the AirConditioner class. 

# ═══ Your First Class: A Simple Sensor ═══

class TemperatureSensor:
    """A temperature sensor — the simplest possible class."""

    def __init__(self, name, location):
        """
        __init__ is the CONSTRUCTOR — it runs when you create an object.
        'self' refers to the specific object being created.

        Think of __init__ like the commissioning process — you set up
        the sensor with its name, location, and initial reading.
        """
        self.name = name              # Attribute: sensor's name
        self.location = location      # Attribute: where it's installed
        self.reading = 0.0            # Attribute: current reading (starts at 0)
        self.unit = "°F"              # Attribute: measurement unit

    def take_reading(self, temperature):
        """Method: take a new reading."""
        self.reading = temperature
        print(f"📡 {self.name} @ {self.location}: {self.reading}{self.unit}")

    def get_status(self):
        """Method: return a formatted status string."""
        return f"{self.name}: {self.reading}{self.unit} ({self.location})"


# Creating OBJECTS (instances) from the class blueprint
supply_sensor = TemperatureSensor("SAT-01", "Supply Air Duct")
return_sensor = TemperatureSensor("RAT-01", "Return Air Plenum")

# Using methods on each object
supply_sensor.take_reading(55.2)   # 📡 SAT-01 @ Supply Air Duct: 55.2°F
return_sensor.take_reading(72.8)   # 📡 RAT-01 @ Return Air Plenum: 72.8°F

# Each object has its OWN data
print(supply_sensor.reading)  # 55.2
print(return_sensor.reading)  # 72.8 — different object, different data!

Understanding self

The word self is Python's way of saying "this specific object." When you have two sensors — supply_sensor and return_sensor — they're both made from the same blueprint, but self ensures each one tracks its own data. Think of it like serial numbers: same model, different units.

❄️ 4.2 — The AirConditioner Class

Now let's refactor our Module 2 functions into a proper class. All four components become methods, and the refrigerant state becomes an attribute: 

class AirConditioner:
    """
    A complete air conditioning system modeled as a Python class.

    Encapsulates the refrigerant state and all four cycle components
    as methods. The AC tracks its own internal state.
    """

    def __init__(self, unit_id, capacity_tons=3.0):
        """Commission the AC unit with initial state."""
        self.unit_id = unit_id
        self.capacity_tons = capacity_tons
        self.cycle_count = 0
        self.is_running = False

        # Internal refrigerant state
        self.refrigerant = {
            "temp": 40.0,
            "pressure": 68,
            "state": "liquid"
        }

        # Operational parameters
        self.evaporator_superheat = 10.0
        self.compression_ratio = 6.0
        self.condenser_approach = 10.0

        print(f"✅ {self.unit_id} commissioned: {self.capacity_tons}-ton unit")

    def evaporator(self, room_temp):
        """Absorb heat from room air. Returns new room temp."""
        self.refrigerant["temp"] += 15.0
        self.refrigerant["state"] = "gas"
        new_room_temp = room_temp - 2.0
        return new_room_temp

    def compressor(self):
        """Compress low-pressure gas into high-pressure gas."""
        self.refrigerant["temp"] += 80.0
        self.refrigerant["pressure"] = int(
            self.refrigerant["pressure"] * self.compression_ratio
        )
        self.refrigerant["state"] = "gas"

    def condenser(self, outdoor_temp):
        """Reject heat to outdoor air, condensing gas to liquid."""
        self.refrigerant["temp"] = outdoor_temp + self.condenser_approach
        self.refrigerant["state"] = "liquid"

    def expansion_valve(self):
        """Drop pressure through orifice, cooling the refrigerant."""
        self.refrigerant["temp"] = 40.0
        self.refrigerant["pressure"] = int(
            self.refrigerant["pressure"] / self.compression_ratio
        )
        self.refrigerant["state"] = "liquid"

    def run_cycle(self, room_temp, outdoor_temp):
        """
        Execute one complete refrigeration cycle.
        Returns the new room temperature.
        """
        self.cycle_count += 1
        self.is_running = True

        room_temp = self.evaporator(room_temp)
        self.compressor()
        self.condenser(outdoor_temp)
        self.expansion_valve()

        return room_temp

    def get_telemetry(self):
        """Return current system telemetry as a dictionary."""
        return {
            "unit_id": self.unit_id,
            "cycle": self.cycle_count,
            "running": self.is_running,
            "ref_temp": self.refrigerant["temp"],
            "ref_pressure": self.refrigerant["pressure"],
            "ref_state": self.refrigerant["state"]
        }

    def __str__(self):
        """Human-readable string representation."""
        status = "RUNNING" if self.is_running else "OFF"
        return (f"[{self.unit_id}] {self.capacity_tons}T | "
                f"Status: {status} | Cycles: {self.cycle_count}")


# ═══ Using the Class ═══
ac = AirConditioner("RTU-01", capacity_tons=5.0)
print(ac)  # [RTU-01] 5.0T | Status: OFF | Cycles: 0

room = 82.0
for i in range(5):
    room = ac.run_cycle(room, outdoor_temp=95.0)
    telemetry = ac.get_telemetry()
    print(f"  Cycle {telemetry['cycle']}: Room = {room:.1f}°F")

print(f"\n{ac}")  # [RTU-01] 5.0T | Status: RUNNING | Cycles: 5

🤖 4.3 — The Robot Class

Our robot is a separate entity that moves, has a position, and contains an air conditioning system. Let's build the Robot class: 

class Robot:
    """
    A robot with movement capabilities and an internal AC system.

    The Robot doesn't inherit from AirConditioner — it CONTAINS one.
    This is called COMPOSITION: Robot HAS-AN AirConditioner.
    """

    def __init__(self, name, x=0, y=0):
        """Create a robot at position (x, y) with an internal AC."""
        self.name = name
        self.x = x
        self.y = y
        self.speed = 1
        self.internal_temp = 72.0  # Robot's internal temperature
        self.max_temp = 100.0      # Overheating threshold
        self.steps_taken = 0

        # COMPOSITION: Robot contains an AirConditioner
        self.ac = AirConditioner(f"{name}-AC", capacity_tons=1.0)

        print(f"🤖 {self.name} initialized at ({self.x}, {self.y})")

    def walk(self, direction, steps=1):
        """Move the robot in a direction. Movement generates heat."""
        for _ in range(steps):
            if direction == "right":
                self.x += self.speed
            elif direction == "left":
                self.x -= self.speed
            elif direction == "up":
                self.y -= self.speed
            elif direction == "down":
                self.y += self.speed

            self.steps_taken += 1

            # Walking generates internal heat (motors, processors, friction)
            self.internal_temp += 0.5

        print(f"🚶 {self.name} walked {direction} {steps} steps → "
              f"({self.x}, {self.y}) | Internal temp: {self.internal_temp:.1f}°F")

    def run(self, direction, steps=1):
        """Run fast — generates MORE heat than walking."""
        old_speed = self.speed
        self.speed = 3  # Running is 3x faster
        self.walk(direction, steps)
        self.internal_temp += 2.0  # Extra heat from running
        self.speed = old_speed
        print(f"   ⚡ Running bonus heat! Temp now: {self.internal_temp:.1f}°F")

    def run_climate_control(self):
        """
        Use the internal AC to cool down the robot.
        This is COMPOSITION in action: Robot delegates cooling to its AC.
        """
        if self.internal_temp > 75.0:
            print(f"🌡️ {self.name} is warm ({self.internal_temp:.1f}°F) — activating AC")
            self.internal_temp = self.ac.run_cycle(
                self.internal_temp,
                outdoor_temp=self.internal_temp + 10  # exhaust is hotter
            )
            print(f"   ❄️ Cooled to {self.internal_temp:.1f}°F")
        else:
            print(f"✅ {self.name} temperature nominal: {self.internal_temp:.1f}°F")

    def status(self):
        """Print full robot status."""
        print(f"""
╔═══════════════════════════════════════╗
║  ROBOT STATUS: {self.name:<20}  ║
╠═══════════════════════════════════════╣
║  Position:     ({self.x:>3}, {self.y:>3})            ║
║  Steps taken:  {self.steps_taken:>6}               ║
║  Internal temp: {self.internal_temp:>5.1f}°F            ║
║  AC unit:      {self.ac.unit_id:<20}  ║
║  AC cycles:    {self.ac.cycle_count:>6}               ║
╚═══════════════════════════════════════╝""")


# ═══ Putting It Together ═══
print("=" * 50)
print("  ROBOT SIMULATION WITH CLIMATE CONTROL")
print("=" * 50)

bot = Robot("Atlas", x=0, y=0)
bot.status()

# Walk around — generates heat
bot.walk("right", 5)
bot.walk("up", 3)
bot.run("right", 4)     # Running generates more heat!
bot.run("down", 2)

# Check temperature and cool down
bot.run_climate_control()
bot.run_climate_control()  # Run again if still warm

bot.status()

🔗 4.4 — Composition: HAS-A vs IS-A

There are two main ways to combine classes in OOP:

PatternRelationshipHVAC ExampleWhen to Use
Composition (HAS-A) Object contains another object An RTU has a compressor, has a fan, has controls When parts are independent and interchangeable
Inheritance (IS-A) Object is a specialized version of another A VRF system is a type of AC system When objects share identity and common behavior

Our Robot uses composition because a Robot is not a type of AirConditioner — it contains one. The robot delegates cooling work to its AC object. This is like how a real robot would have a cooling module installed inside it — a separate component that can be swapped, upgraded, or maintained independently. 

# Composition in one line:
self.ac = AirConditioner(f"{name}-AC", capacity_tons=1.0)

# The Robot doesn't know HOW the AC works internally.
# It just calls self.ac.run_cycle() and gets a result.
# This is called ENCAPSULATION — hiding complexity behind a simple interface.

# You could swap in a different cooling system:
# self.cooler = LiquidCoolingSystem(...)
# self.cooler = ThermoelectricCooler(...)
# The Robot code barely changes — just the method call.

🎯 Module 4 Key Takeaways

  • Classes are blueprints that bundle data (attributes) and behavior (methods).
  • __init__ is the constructor — it sets up initial state when you create an object.
  • self refers to the specific object instance — like a serial number.
  • Methods are functions that belong to a class and operate on self.
  • Composition (HAS-A) means an object contains other objects — Robot HAS-AN AirConditioner.
  • Composition lets you build complex systems from simple, reusable parts.
