AI Integration

Gemini API & Robot Brain

Modern HVAC systems use analytics platforms and AI to monitor performance, predict failures, and recommend maintenance. In this module, you'll give your robot a brain powered by Google's Gemini AI — it reads live telemetry data and answers questions about the robot's thermal state in natural language.

🌐 5.1 — What Is an API?

An API (Application Programming Interface) is a way for two programs to talk to each other. Think of it like a thermostat communicating with an RTU:

  • The thermostat (your program) sends a request: "What's the current temperature?"
  • The RTU (the API server) sends a response: "72.5°F"
  • They communicate using a protocol (BACnet in HVAC, HTTP for web APIs)

Google's Gemini API works the same way. Your Python program sends a text prompt to Google's servers, and Gemini sends back an intelligent response. The "protocol" is HTTPS, and the "language" is the Gemini SDK.

API Keys — Your Access Badge

Just like you need a keycard to access a building's mechanical room, you need an API key to access the Gemini API. This key identifies you and controls your access level. 

# ⚠️ NEVER put your API key directly in code!
# Bad:  api_key = "AIzaSy..."  ← Anyone who sees your code gets your key

# ✅ Use environment variables instead:
# An environment variable is a value stored in your operating system,
# not in your code. It's like keeping the master key in a lockbox,
# not taped to the door.

import os

# This reads the API key from your system environment
api_key = os.environ.get("GEMINI_API_KEY")

if api_key:
    print("✅ API key loaded successfully")
else:
    print("❌ No API key found!")
    print("   Set it with: export GEMINI_API_KEY='your-key-here'")

Understanding the SDK Pattern

The SDK (Software Development Kit) handles all the complicated networking for you. It's like using a handheld diagnostic tool to talk to an RTU controller — you don't need to know the raw BACnet protocol, the tool handles it. Similarly, the Gemini SDK handles HTTP requests, authentication, and response parsing.

🧠 5.3 — The RobotBrain Class

Now let's build the intelligence layer. The RobotBrain class wraps the Gemini API and gives it context about the robot's current state via system instructions — a prompt that tells the AI who it is and what data it has access to: 

import google.generativeai as genai
import os
from datetime import datetime

class RobotBrain:
    """
    AI-powered brain for the Robot, using Google Gemini.

    The brain receives live telemetry data from the robot's sensors
    and AC system, then uses Gemini to reason about the data and
    answer questions in natural language.
    """

    def __init__(self, robot_name):
        """Initialize the brain with Gemini API connection."""
        self.robot_name = robot_name
        self.conversation_history = []

        # Configure Gemini
        api_key = os.environ.get("GEMINI_API_KEY")
        if not api_key:
            raise ValueError(
                "❌ GEMINI_API_KEY not set! "
                "Run: export GEMINI_API_KEY='your-key'"
            )

        genai.configure(api_key=api_key)
        self.model = genai.GenerativeModel("gemini-pro")

        print(f"🧠 {robot_name} Brain initialized — Gemini connected")

    def build_system_prompt(self, robot_telemetry, ac_telemetry):
        """
        Build a system instruction with live telemetry data.

        This is like giving a technician the current readings before
        asking them to diagnose an issue. The AI needs context.
        """
        prompt = f"""You are the AI brain of a robot named {self.robot_name}.
You are an expert HVAC technician and robotics engineer.

CURRENT TELEMETRY (live sensor data):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Timestamp: {datetime.now().isoformat()}

ROBOT STATUS:
  Position: ({robot_telemetry['x']}, {robot_telemetry['y']})
  Internal Temperature: {robot_telemetry['internal_temp']:.1f}°F
  Steps Taken: {robot_telemetry['steps_taken']}
  Max Safe Temp: {robot_telemetry['max_temp']:.1f}°F

AC SYSTEM ({ac_telemetry['unit_id']}):
  Running: {ac_telemetry['running']}
  Cycle Count: {ac_telemetry['cycle']}
  Refrigerant Temp: {ac_telemetry['ref_temp']:.1f}°F
  Refrigerant Pressure: {ac_telemetry['ref_pressure']} PSI
  Refrigerant State: {ac_telemetry['ref_state']}

OPERATING RULES:
- Normal internal temp range: 68-78°F
- Warning range: 78-90°F
- Critical/overheating: above 90°F
- Superheat target: 8-12°F
- Subcooling target: 10-15°F

Answer questions about your own status, diagnose issues, and
recommend actions based on the live telemetry data above.
Use HVAC terminology when appropriate. Be concise but thorough."""

        return prompt

    def think(self, question, robot_telemetry, ac_telemetry):
        """
        Ask the robot brain a question with live telemetry context.

        Args:
            question: The user's question
            robot_telemetry: dict with robot sensor data
            ac_telemetry: dict with AC system data

        Returns:
            str: The AI's response
        """
        system_prompt = self.build_system_prompt(
            robot_telemetry, ac_telemetry
        )

        # Combine system prompt with user question
        full_prompt = f"{system_prompt}\n\nUSER QUESTION: {question}"

        try:
            response = self.model.generate_content(full_prompt)
            answer = response.text

            # Log the conversation
            self.conversation_history.append({
                "timestamp": datetime.now().isoformat(),
                "question": question,
                "answer": answer
            })

            return answer

        except Exception as e:
            return f"❌ Brain error: {e}"

💬 5.4 — Interactive CLI: Talk to Your Robot

Let's build a command-line interface where you can type questions and the robot answers using live telemetry. This combines the Robot from Module 4 with the RobotBrain: 

# ═══ INTERACTIVE ROBOT CLI ═══
# Combines: Robot (Module 4) + RobotBrain (Module 5)

def interactive_robot_session():
    """Run an interactive session with the AI-powered robot."""

    # Create the robot and its brain
    bot = Robot("Atlas", x=0, y=0)
    brain = RobotBrain("Atlas")

    # Simulate some activity to generate interesting telemetry
    bot.walk("right", 10)
    bot.run("up", 5)
    bot.run_climate_control()

    print("\n" + "=" * 55)
    print("  🤖 ROBOT ATLAS — Interactive AI Session")
    print("  Type questions about the robot's status.")
    print("  Commands: 'walk', 'run', 'cool', 'status', 'quit'")
    print("=" * 55)

    while True:
        user_input = input("\n👤 You: ").strip()

        if not user_input:
            continue

        if user_input.lower() == "quit":
            print("👋 Session ended.")
            break

        # Handle action commands
        if user_input.lower() == "status":
            bot.status()
            continue
        elif user_input.lower().startswith("walk"):
            bot.walk("right", 3)
            continue
        elif user_input.lower().startswith("run"):
            bot.run("right", 5)
            continue
        elif user_input.lower() == "cool":
            bot.run_climate_control()
            continue

        # For questions, use the AI brain
        robot_telemetry = {
            "x": bot.x,
            "y": bot.y,
            "internal_temp": bot.internal_temp,
            "steps_taken": bot.steps_taken,
            "max_temp": bot.max_temp
        }
        ac_telemetry = bot.ac.get_telemetry()

        print("\n🧠 Atlas is thinking...")
        answer = brain.think(user_input, robot_telemetry, ac_telemetry)
        print(f"\n🤖 Atlas: {answer}")

📝 5.5 — Prompt Engineering: Talking to AI Effectively

The quality of the AI's response depends heavily on how you structure the prompt. This is called prompt engineering. Here are the key principles we used in the RobotBrain:

PrincipleWhat We DidWhy It Matters
Role Assignment "You are the AI brain of a robot... expert HVAC technician" Tells the AI what persona and expertise to use
Context Data Live telemetry values embedded in the prompt The AI can't read your sensors — you must provide the data
Operating Rules Normal/warning/critical temp ranges defined Gives the AI decision criteria for diagnosis
Response Format "Be concise but thorough, use HVAC terminology" Controls the style and length of responses 
# ═══ Prompt Engineering Tips ═══

# BAD prompt — too vague:
bad_prompt = "Tell me about the robot."
# AI doesn't know WHICH robot, what data it has, or what you want.

# GOOD prompt — specific with context:
good_prompt = """You are an HVAC diagnostic AI.

Current readings from RTU-01:
- Supply air: 55°F
- Return air: 72°F
- Discharge: 450 PSI (normal: 380-420)
- Suction: 58 PSI (normal: 65-72)

The discharge pressure is HIGH and suction is LOW.
What is the most likely cause? Recommend diagnostic steps."""

# The AI now has everything it needs to give a useful answer.

🎯 Module 5 Key Takeaways

  • APIs let programs talk to each other — like a thermostat communicating with an RTU.
  • API keys should NEVER be in your code — use environment variables (os.environ).
  • The Gemini SDK handles networking complexity — you just call generate_content().
  • System instructions give the AI context — role, data, rules, format.
  • Prompt engineering is the skill of structuring prompts for better AI responses.
  • Composition continues: Robot HAS-A Brain (RobotBrain), which HAS-A Gemini model.
